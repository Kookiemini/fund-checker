# Что сделать команде (по шагам, порядок важен)

Код, тесты, скрипт доказательств и страница Rule Lab готовы. Ниже то, что по правилам задания делает **сама команда**
(уровень RED: без ИИ, об этом спросят на Quiz 2 и на защите), и порядок, в котором это делать, чтобы не потерять баллы.
Этот файл можно удалить перед сдачей.

## 0. Подготовка (один раз)
1. Положите проект в репозиторий Assignment 1 (новая ветка `ga2`):
   ```
   git checkout -b ga2
   git add .
   git commit -m "GA2: Rule Lab core, evidence script, templates"
   ```
2. Установите новую библиотеку: `pip install -r requirements.txt` (добавлен `matplotlib`).
3. Запустите `pytest`: должно быть `124 passed, 1 skipped` (пропущен только toy-тест, его заполняете вы).

## 1. ДО любых результатов (гейт G0) — RED
⚠️ Пока не сделан этот шаг, **не запускайте** `make_evidence.py` и **не открывайте** страницу `/rule-lab`
(она сама считает результаты при первом заходе). Правило «drop the rule if…» должно быть написано ДО результатов.

1. `RULE_CARD.md`: напишите своими словами **R3** (сигнал), **R4** (позиция для каждого значения сигнала, включая «вне рынка»),
   **R5** (тайминг: информация → решение → доходность), **R8** (когда отказываемся от правила). Сверьтесь с функциями,
   названными рядом с каждым полем.
2. Toy-тест: в `tests/test_rule.py` уже есть 6 цен (`TOY_PRICES`), N = 3, ставка 1.2% годовых. Посчитайте **на бумаге**
   скользящую среднюю, сигнал, позицию и доходность правила в месяцах 4–6 и впишите их в `TOY_EXPECTED`.
   Запустите `pytest`: теперь должно быть `125 passed`. Если toy-тест не проходит — ищите, где ошибка: на бумаге или в коде.
3. Подготовьте объяснение двух canary-тестов (что они ловят и почему) — устно, своими словами.
4. Commit: `git commit -am "G0: Rule Card v1 (R3-R5, R8), toy test"`.

## 2. Первый запуск (G0: первая строка в trials.csv)
```
python make_evidence.py
```
Появятся `evidence/` и строки в `trials.csv`. Это только период разработки (train + validation); test закрыт.
Проверка здравого смысла: если Sharpe правила выше 1.2 — ищите look-ahead. Цифры лекции (Sharpe ≈ 0.55 vs 0.45)
посчитаны на 1927–2026, у нас 2001–2026, поэтому совпадать не обязаны — сравните направление и порядок величин.
Commit: `git add -A && git commit -m "G0: first evidence run"`.

## 3. Гейт G1 (начало недели 12)
Поправьте Rule Card по отзыву преподавателя, запишите изменения в `DECISIONS.md` (дата, решение, альтернативы, кто решил).
Таблица «gross vs net» уже генерируется (E3) — посмотрите её и решите, достаточно ли уровней издержек.

## 4. Гейт G2 — заморозка (конец недели 13)
```
git tag freeze-w13
git push origin ga2 --tags
```
После заморозки любое изменение правила: новая запись в `DECISIONS.md` + новая `RULE_VERSION` в `rule.py` (например `v2`).
Новая версия сама считается новыми попытками в `trials.csv`.

## 5. Открыть test-период ОДИН раз (после заморозки)
```
python make_evidence.py --open-test
```
Дата запишется в `DECISIONS.md` и в `evidence/test_opened.json`. Второй раз скрипт не даст открыть без `--reopen`
(и тогда это тоже запишется). Допишите в `DECISIONS.md`, кто решил открыть.

## 6. Result Card — RED
Откройте `evidence/result_card_numbers.md` и перенесите числа в `RESULT_CARD.md`.
Строку **Verdict** и **Limits** пишете сами: отличима ли разница Sharpe от нуля (смотрите, внутри ли 0 в интервале),
что правило реально меняет (риск, доходность, поведение), выдерживает ли проверку дат начала (E4), плато или пик у соседей (E5),
сколько конфигураций попробовано и сколько раз открыт test. Без «доказывает» и без «обыгрывает рынок» без интервала.
Когда в строке Verdict не останется «…», она появится на странице Rule Lab.

## 7. Перед сдачей
1. `AI_USE.md`: заполните последнюю колонку (что оставили, что поменяли) и добавьте свои записи с датами.
2. `CONTRIBUTIONS.md`: каждый участник — что сделал, что проверил, что может объяснить без компьютера.
3. `REUSE_CHANGES.md`: допишите места `[team]` (отзыв на Assignment 1, почему поменяли главную страницу).
4. Проверьте `DECISIONS.md`: у каждой строки «Who decided» — ваши имена. Сверьте формулы SE Sharpe и «лучшего из шума»
   со слайдами недели 11; если на слайдах другая формула — скажите мне, поменяю.
5. `pytest` → `125 passed`. `python app.py` → `/rule-lab` открывается, числа совпадают с `evidence/evidence_table.md`.
6. Commit, push, в Teams — ссылка на репозиторий и хеш коммита (`git log -1 --format=%H`).

## Что каждый должен уметь объяснить (Quiz 2, защита)
- Почему позиция — это сигнал прошлого месяца (`shift(1)`) и что сломается без этого (canary-тесты).
- Откуда кэш берёт доходность и почему ставка тоже сдвинута на месяц.
- Как считаются издержки и что такое break-even cost.
- Что такое стандартная ошибка Sharpe, парный бутстреп и почему «0 внутри интервала» значит «не отличимо от нуля».
- Зачем train / validation / test и почему test открывается один раз.
- Что такое «ожидаемый Sharpe лучшего из N шумовых правил» и как с ним сравнить ваш лучший Sharpe.
